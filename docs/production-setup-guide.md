# GroundTruth — Production Setup & Environment Configuration Guide

This guide contains the complete, step-by-step instructions to configure, deploy, and operate GroundTruth in a live AWS production environment.

---

## 1. Complete Environment Variables Reference

The application uses environment variables across three levels: root, backend API (`apps/api`), and frontend web app (`apps/web`).

| Variable Name | Environment | Sample Production Value | Description & Source |
| :--- | :--- | :--- | :--- |
| `AWS_REGION` | Root & API | `us-east-1` | AWS deployment region (e.g. `us-east-1`, `ap-south-1`). |
| `APP_ENV` | All | `production` | Deployment environment (`production`, `staging`, `development`). |
| `S3_BUCKET` | API | `groundtruth-evidence-vault-prod-123456789012` | S3 bucket name created by AWS CDK for evidence and policy storage. |
| `DYNAMODB_PREFIX` | API | `groundtruth_` | DynamoDB table name prefix. |
| `DYNAMODB_FINDINGS_TABLE` | API | `groundtruth_findings_prod` | DynamoDB table name for findings and state tracking. |
| `DYNAMODB_AUDIT_TABLE` | API | `groundtruth_audit_log_prod` | DynamoDB table name for chronological audit trails. |
| `COGNITO_USER_POOL_ID` | API & Web | `us-east-1_GROUNDTRUTH_POOL` | Amazon Cognito User Pool ID from CDK output or AWS Console. |
| `COGNITO_CLIENT_ID` | API & Web | `groundtruth-web-client-id` | Amazon Cognito Web App Client ID (no secret). |
| `SAGEMAKER_ENDPOINT_NAME` | API | `groundtruth-vision-reasoner-prod` | Name of the hosted Amazon SageMaker real-time inference endpoint. |
| `AI_PROVIDER` | API | `sagemaker` (or `demo`) | Active AI engine: `sagemaker` for live AWS inference, `demo` for zero-fail offline judge evaluation. |
| `API_GATEWAY_URL` | API & Web | `https://api.groundtruth.aws` | Public API Gateway endpoint URL generated by CDK. |
| `EVENT_BUS_NAME` | API | `groundtruth-domain-events-prod` | Custom Amazon EventBridge bus name for domain events. |
| `SNS_TOPIC_ARN` | API | `arn:aws:sns:us-east-1:...` | Amazon SNS Topic ARN for critical safety breach alerts. |
| `MAX_UPLOAD_SIZE_MB` | API | `25` | Maximum allowed evidence photograph / policy PDF upload size (MB). |
| `PRESIGNED_URL_EXPIRES_IN_SEC` | API | `900` | Expiration time for S3 presigned PUT/GET URLs in seconds (15 minutes). |

## 2. Production Deployment Step-by-Step

### Phase 1: AWS Credentials & CLI Setup
Ensure you have administrative credentials configured for your AWS account:
```powershell
aws configure
# AWS Access Key ID: <Your-Access-Key>
# AWS Secret Access Key: <Your-Secret-Key>
# Default region name: us-east-1
# Default output format: json
```

Verify your active account identity:
```powershell
aws sts get-caller-identity
```

---

### Phase 2: Compile Workspaces & Synthesize CDK Infrastructure
From the project root directory:

```powershell
# 1. Install all dependencies
npm install

# 2. Compile TypeScript across all packages
npm run build

# 3. Bootstrap CDK in your AWS account (if not done previously)
cd infrastructure
npx cdk bootstrap aws://<ACCOUNT_ID>/us-east-1

# 4. Synthesize CloudFormation templates
npm run synth

# 5. Deploy full Ship It stack to AWS
npx cdk deploy GroundTruthStack --require-approval never
```

**Note the outputs displayed in the terminal:**
- `GroundTruthStack.ApiGatewayUrl`
- `GroundTruthStack.EvidenceBucketName`
- `GroundTruthStack.CognitoUserPoolId`
- `GroundTruthStack.CognitoClientId`
- `GroundTruthStack.SageMakerEndpointName`
- `GroundTruthStack.StepFunctionsArn`

Update your `.env` file with these generated production values.

---

### Phase 3: Deploy Amazon SageMaker Inference Model
Navigate to the SageMaker service directory and launch the hosted PyTorch vision reasoner endpoint:

```powershell
cd ../services/sagemaker

# Install Python requirements
python -m pip install -r requirements.txt

# Deploy real-time endpoint
python deploy_endpoint.py
```

*Cost Control Notice:* To shut down the endpoint after testing or hackathon judging to avoid ongoing charges, simply run:
```powershell
python teardown_endpoint.py
```

---

### Phase 4: Deploy Frontend Single-Page App to Amazon Amplify Hosting
1. Open the **AWS Amplify Console** in your browser.
2. Click **Host web app** → Select **GitHub** and authorize your repository (`GROUNDTRUTH-first-commit-hackathon`).
3. Select your primary branch (`main`).
4. In the App settings, set the App root to: `apps/web`.
5. Under Build and test settings, use:
```yaml
version: 1
frontend:
  phases:
    preBuild:
      commands:
        - npm ci
    build:
      commands:
        - npm run build --workspace=apps/web
  artifacts:
    baseDirectory: apps/web/dist
    files:
      - '**/*'
  cache:
    paths:
      - node_modules/**/*
```
6. Add the environment variables (`VITE_API_BASE_URL`, `VITE_AWS_REGION`, `VITE_COGNITO_USER_POOL_ID`, `VITE_COGNITO_CLIENT_ID`) in Amplify Console under **App Settings → Environment variables**.
7. Click **Save and Deploy**. Amplify will build and assign a public `https://<app-id>.amplifyapp.com` domain.

---

### Phase 5: Seed Operational Dataset & Run Smoke Tests
Once the backend and database tables are deployed:

```powershell
# Seed realistic policies, requirements, and findings
npm run seed

# Execute AWS production smoke test
npm run smoke-test
```
